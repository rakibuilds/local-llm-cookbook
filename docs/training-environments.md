# Training Environments

This guide explains how to prepare CPU and NVIDIA GPU environments for the
Local LLM Cookbook distillation examples.

## 1. Shared architecture

The initial training implementation uses:

- PyTorch for model computation.
- Hugging Face Transformers for model loading and training.
- PEFT for parameter-efficient fine-tuning with LoRA.
- Accelerate for device and training configuration.
- Safetensors for safe model weight storage.
- PyYAML for training configuration files.

The initial workflow uses response-based supervised fine-tuning (SFT).
It does not require teacher logits.

## 2. Python environment

Use Python 3.10 or later. Python 3.11 or 3.12 is recommended.

Create an isolated virtual environment from the repository root:

### Windows PowerShell

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
```

If PowerShell blocks activation, use:

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\.venv\Scripts\Activate.ps1
```

### Linux

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
```

## 3. CPU environment

Use this path for CPU-only experiments and systems without a supported
CUDA GPU.

Install the official CPU build of PyTorch:

```powershell
python -m pip install torch --index-url https://download.pytorch.org/whl/cpu
```

Then install the shared training dependencies:

```powershell
python -m pip install -r requirements/cpu.txt
```

CPU training can be slow, particularly for models with hundreds of millions
or billions of parameters. Begin with a small model, short sequences and
small batches.

The system may use shared memory for integrated graphics, but this does not
provide the same training performance as a supported dedicated GPU.

## 4. NVIDIA GPU environment

Use this path when a compatible NVIDIA GPU and driver are available.

1. Install or update the NVIDIA driver.
2. Check that the GPU is detected with `nvidia-smi`.
3. Visit the official PyTorch installation selector:
   https://pytorch.org/get-started/locally/
4. Select the operating system, package manager, Python and an available
   CUDA compute platform.
5. Run the installation command generated by the selector.
6. Install the shared dependencies:

```powershell
python -m pip install -r requirements/nvidia.txt
```

The PyTorch CUDA wheel includes its required CUDA runtime components.
A separate full CUDA Toolkit installation is not always required for
ordinary PyTorch training.

Verify CUDA availability:

```powershell
python -c "import torch; print('PyTorch:', torch.__version__); print('CUDA available:', torch.cuda.is_available()); print('GPU:', torch.cuda.get_device_name(0) if torch.cuda.is_available() else 'Not available')"
```

A CUDA-enabled PyTorch build does not guarantee that every GPU, driver,
quantization library or training configuration is compatible.

## 5. LoRA and QLoRA

The initial shared training workflow focuses on LoRA.

LoRA freezes the pretrained model weights and trains additional low-rank
adapter parameters. It reduces trainable parameters, but it does not make
all model sizes or sequence lengths fit into limited memory.

QLoRA adds quantization of the frozen base model while training adapters.
It requires additional compatible quantization libraries and hardware.

QLoRA dependencies are intentionally not included in the base NVIDIA
requirements file. Check the current compatibility of the operating
system, Python, PyTorch, CUDA and quantization library before installing
them. Linux or WSL2 may be preferable for some QLoRA configurations.

## 6. Verify the environment

Run:

```powershell
python -c "import torch, transformers, peft, accelerate, yaml; print('PyTorch:', torch.__version__); print('Transformers:', transformers.__version__); print('PEFT:', peft.__version__); print('Accelerate:', accelerate.__version__); print('Environment imports: OK')"
```

For CPU systems, CUDA availability is expected to be False.

For NVIDIA systems, verify that CUDA is available and that the expected GPU
is detected before starting training.

## 7. Reproducibility

Record the following for every experiment:

- Python version.
- Operating system.
- PyTorch version and CUDA availability.
- Transformers, PEFT and Accelerate versions.
- Student model ID and revision.
- Dataset version and split.
- Training configuration and random seed.
- Hardware and memory information.

For reproducible releases, capture tested package versions in a lock file
or environment export. Avoid assuming that an unpinned dependency file
reproduces an identical environment indefinitely.

## 8. Hardware guidance

Choose a model and training strategy based on available system memory,
GPU memory, model architecture, sequence length, batch size and optimizer.

Do not estimate training feasibility using model weight size alone.
Training also requires memory for activations, gradients, optimizer state,
temporary tensors and runtime overhead.

See the Hardware Guide for further guidance.
