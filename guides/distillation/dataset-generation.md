# Dataset Generation for Model Distillation

A distillation dataset contains the examples used to teach a student model to reproduce selected teacher-model capabilities.

For response-based distillation, these examples typically contain an input prompt and a response generated by the teacher.

Dataset quality is critical. Large datasets are not automatically better. A smaller, diverse, accurate, and carefully reviewed dataset can be more useful than a large collection of repetitive or incorrect responses.

## 1. Understand the Dataset Generation Workflow

A typical response-based dataset generation workflow:

```text
        Task Definition
              |
              v
        Prompt Collection
              |
              v
        Teacher Model
              |
              v
       Generated Responses
              |
              v
      Validation and Cleaning
              |
              v
        Dataset Formatting
              |
              v
       Training and Evaluation
```

The objective is to create reliable examples that represent the tasks the student is expected to perform.

## 2. Define the Target Tasks

Start by deciding what the student should learn.

Possible task categories include:

| Task | Example |
|---|---|
| Explanation | Explain a technical concept. |
| Question answering | Answer a factual question. |
| Summarization | Summarize a passage. |
| Coding | Generate a Python function. |
| Translation | Translate between supported languages. |
| Classification | Assign a category to an input. |
| Instruction following | Follow a structured user instruction. |

For specialized models, include examples that reflect the intended domain.

For example, an Assamese-language assistant should include representative Assamese prompts and responses rather than relying entirely on English examples.

## 3. Prepare Prompts

Prompts are the inputs used to obtain training responses from the teacher.

Good prompts should be:

- Clear and unambiguous.
- Representative of real user requests.
- Diverse in wording and difficulty.
- Relevant to the target application.
- Free from unnecessary duplication.

Example prompt collection:

```json
[
  {
    "id": "example-001",
    "task": "explanation",
    "prompt": "Explain what an LLM is in simple language."
  },
  {
    "id": "example-002",
    "task": "coding",
    "prompt": "Write a Python function that checks whether a number is prime."
  },
  {
    "id": "example-003",
    "task": "summarization",
    "prompt": "Summarize the benefits of running language models locally."
  }
]
```

This is an illustrative prompt collection, not a completed training dataset.

## 4. Generate Responses from the Teacher

Send prompts to the selected teacher model and store its responses.

For a local teacher running through Ollama, the local API can generate responses without requiring a cloud inference API.

Example request:

```python
import requests

response = requests.post(
    "http://localhost:11434/api/chat",
    json={
        "model": "qwen3:0.6b",
        "messages": [
            {
                "role": "user",
                "content": "Explain what an LLM is in simple language."
            }
        ],
        "stream": False
    },
    timeout=120
)

response.raise_for_status()

data = response.json()
teacher_response = data["message"]["content"]

print(teacher_response)
```

The example uses a small model for demonstrating the workflow. Select a teacher based on actual task quality, not model size alone.

For production dataset generation, also consider:

- Request timeouts.
- Retry handling.
- Rate limits.
- Response validation.
- Logging.
- Reproducibility.
- Teacher model version.

Do not assume that a successful API response is automatically a high-quality training example.

## 5. Recommended Dataset Format

JSONL (JSON Lines) is a convenient format for storing training examples.

Each line contains one independent JSON object.

A recommended conversation-style example:

```json
{"messages":[{"role":"user","content":"What is quantization?"},{"role":"assistant","content":"Quantization reduces the numerical precision used to represent model weights or computations, often reducing memory requirements."}]}
{"messages":[{"role":"user","content":"What is local inference?"},{"role":"assistant","content":"Local inference means running a trained model on your own hardware rather than sending inference requests to a remote model service."}]}
```

This format is commonly supported by instruction-tuning workflows, but exact schema requirements depend on the training framework.

For tracking dataset metadata, you can also maintain fields such as:

```json
{
  "id": "example-001",
  "task": "explanation",
  "prompt": "What is quantization?",
  "response": "Quantization reduces numerical precision...",
  "teacher_model": "example-teacher",
  "source": "teacher-generated",
  "review_status": "pending"
}
```

The metadata format is intended for dataset preparation. Convert it into the format required by your training framework before training.

## 6. Dataset Quality Control

Teacher-generated responses should be reviewed before they are used for training.

### 6.1 Check correctness

Look for:

- Incorrect facts.
- Invalid code.
- Unsupported claims.
- Contradictory statements.
- Incorrect translations.

For factual tasks, compare responses against trusted references or verified answers.

### 6.2 Remove duplicates

Repeated prompts and near-identical responses can reduce dataset diversity.

Use exact duplicate detection and, where useful, semantic similarity checks.

### 6.3 Check formatting

Verify that:

- Every record is valid JSON.
- Required fields are present.
- Responses are not empty.
- Text encoding is consistent.
- Conversation roles are valid.
- Special characters are preserved.

### 6.4 Filter low-quality responses

Consider rejecting examples that contain:

- Empty responses.
- Unrelated content.
- Repeated filler text.
- Malformed output.
- Unwanted refusal responses.
- Excessive formatting errors.

Do not automatically remove every refusal. If the student is expected to handle unsafe or inappropriate requests correctly, suitable safety examples may be important.

## 7. Dataset Diversity

A useful dataset should represent the range of tasks the student is expected to handle.

Include:

- Short and long prompts.
- Different wording styles.
- Easy and difficult examples.
- Different relevant topics.
- Realistic user instructions.
- Relevant edge cases.

Avoid overrepresenting a single prompt pattern.

For multilingual projects, evaluate language quality separately and make sure the dataset represents the languages and scripts required by the application.

## 8. Train, Validation, and Test Splits

Separate examples into distinct datasets.

| Split | Purpose |
|---|---|
| Training | Used to update student model parameters. |
| Validation | Used to monitor training and tune configuration. |
| Test | Used for final evaluation. |

A possible starting split is:

- 80% training.
- 10% validation.
- 10% testing.

These percentages are illustrative, not mandatory.

Avoid placing near-duplicate prompts or responses across different splits. Otherwise, evaluation results may be misleading.

Keep the test dataset separate from the training process.

## 9. Dataset Size

There is no universal minimum dataset size for distillation.

Start with a small pilot dataset to validate the complete pipeline.

Then increase dataset size based on:

- Task diversity.
- Student model capacity.
- Response quality.
- Training performance.
- Evaluation results.
- Available compute resources.

A larger dataset is useful only when its additional examples contribute meaningful learning signals.

## 10. Dataset Licensing and Privacy

Before generating or distributing a dataset, check:

- Teacher model license and terms.
- Source dataset license.
- Restrictions on generated outputs.
- Personal or confidential information.
- Sensitive data in prompts and responses.
- Third-party copyrighted material.

Do not include private information in teacher prompts without appropriate authorization.

Do not assume that generated training data is automatically free of licensing or privacy restrictions.

## 11. Dataset Generation Checklist

- [ ] Define the target tasks.
- [ ] Prepare representative prompts.
- [ ] Select and document the teacher model.
- [ ] Generate responses.
- [ ] Validate JSON and required fields.
- [ ] Review factual correctness.
- [ ] Remove duplicates and unsuitable examples.
- [ ] Check language and formatting quality.
- [ ] Create training, validation, and test splits.
- [ ] Review licensing and privacy requirements.
- [ ] Preserve dataset versions and generation settings.
