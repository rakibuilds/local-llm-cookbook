# Knowledge Distillation

Knowledge distillation is a machine learning technique that transfers useful knowledge or behavior from a larger model (the **teacher**) to a smaller model (the **student**).

In the context of Large Language Models (LLMs), distillation can help create smaller models that perform selected tasks with lower memory requirements and inference costs.

The goal is not necessarily to reproduce every capability of the teacher. Instead, the student is trained to retain the capabilities that matter for its intended use.

## 1. Teacher–Student Architecture

A typical distillation workflow involves three main components:

1. **Teacher model:** A larger or more capable model that provides training signals.
2. **Distillation dataset:** Inputs, teacher-generated responses, probability distributions, or other training signals.
3. **Student model:** A smaller model trained to learn from the teacher.

### Basic workflow

```text
             Input Prompts
                   |
                   v
          +------------------+
          |   Teacher Model  |
          |   (Larger LLM)   |
          +------------------+
                   |
                   v
          Teacher Outputs
          or Training Signals
                   |
                   v
          +------------------+
          | Distillation     |
          | Dataset          |
          +------------------+
                   |
                   v
          +------------------+
          |   Student Model  |
          |   (Smaller LLM)  |
          +------------------+
                   |
                   v
          Evaluation and Testing
```

The student learns from the teacher's outputs or other training signals, depending on the distillation method.

## 2. Why Distill Language Models?

Large models can require substantial GPU memory, storage, and computational resources.

Distillation can help:

- Reduce inference memory requirements by using a smaller student architecture.
- Improve deployment efficiency for selected tasks.
- Adapt a general-purpose model to a narrower domain.
- Create specialized models for local applications.
- Reduce serving costs when the student meets the required quality threshold.

However, distillation does not automatically reduce memory or improve speed. Those benefits depend primarily on the student architecture, parameter count, precision, runtime, and hardware.

A smaller student may also lose important capabilities or reproduce errors and biases present in teacher-generated data.

## 3. Main Distillation Approaches

There are several approaches to transferring knowledge from a teacher to a student.

### 3.1 Response-Based Distillation

Response-based distillation trains a student using examples generated by a teacher.

The teacher receives prompts and produces responses. These responses are collected into a dataset and used to train the student.

Example:

**Prompt:**

```text
Explain what quantization means in machine learning.
```

**Teacher response:**

```text
Quantization reduces the numerical precision used to represent
model weights or computations. It can reduce memory usage
and improve inference efficiency.
```

The prompt and teacher response become a supervised training example.

This approach is especially practical because it does not require access to the teacher's internal logits or hidden representations.

It is commonly called response distillation or synthetic-data distillation.

### 3.2 Logit-Based Distillation

Logit-based distillation uses the teacher's output logits or probability distributions.

A logit is an unnormalized numerical score assigned to a possible next token before applying a probability transformation such as softmax.

Instead of learning only from the teacher's selected response token, the student can learn from the teacher's distribution over multiple possible tokens.

This provides a richer training signal.

A common approach uses a temperature parameter to soften probability distributions.

For teacher logits \(z_i\), the probability of token \(i\) is:

\[
p_i = \operatorname{softmax}\left(\frac{z_i}{T}\right)
\]

Where:

- \(z_i\) is the logit for token \(i\).
- \(T\) is the temperature.
- \(p_i\) is the resulting probability.

Higher temperatures generally produce softer distributions, making less likely alternatives more visible.

A common logit-distillation objective uses Kullback–Leibler divergence:

\[
L_{\text{KD}} =
T^2 D_{\text{KL}}
\left(
P_{\text{teacher}}^T
\parallel
P_{\text{student}}^T
\right)
\]

The exact objective and scaling depend on the implementation.

**Important:** Logit-based distillation requires access to teacher logits or equivalent probability information. An ordinary text-generation API that returns only text is not sufficient.

### 3.3 Feature-Based Distillation

Feature-based distillation transfers selected internal representations from the teacher to the student.

These representations may include:

- Hidden states.
- Intermediate layer outputs.
- Attention-related representations.

The student is trained to reproduce selected teacher representations or their transformations.

Teacher and student architectures may have different dimensions or numbers of layers. Additional projection layers or mapping strategies may therefore be required.

### 3.4 Relation-Based Distillation

Relation-based distillation focuses on relationships between examples or representations.

For example, the student may learn similarities or relative distances between representations produced by the teacher.

This can be useful when preserving relationships between samples is more important than matching individual internal activations.

## 4. Black-Box vs. White-Box Distillation

The available information about the teacher determines which approaches are practical.

| Approach | Teacher information required | Typical methods |
|---|---|---|
| Black-box | Generated text or API responses | Response-based distillation |
| White-box | Logits, hidden states, or internal representations | Logit-, feature-, and relation-based methods |

### Black-box distillation

The teacher is treated as a text-generation system.

Typical workflow:

1. Prepare input prompts.
2. Send prompts to the teacher.
3. Collect generated responses.
4. Validate and clean the responses.
5. Train the student on the resulting dataset.

This approach works with many local inference tools and text-generation APIs, subject to their usage terms.

### White-box distillation

The teacher's internal training signals are available.

Typical workflow:

1. Load or access the teacher model.
2. Run input examples through the teacher.
3. Extract logits or selected internal representations.
4. Calculate a distillation loss.
5. Update the student model.

This approach provides richer training signals but requires more implementation work and often more GPU memory.

## 5. Distillation and Supervised Fine-Tuning

Response-based distillation is closely related to supervised fine-tuning (SFT).

In both approaches, a model learns from input-output examples.

The difference is primarily where the training examples originate:

| Supervised fine-tuning | Response-based distillation |
|---|---|
| Uses labeled or curated examples. | Uses teacher-generated or teacher-assisted examples. |
| Responses may come from human annotators or existing datasets. | Responses are generated by a teacher model. |
| Focuses on adapting a pretrained model. | Focuses on transferring selected teacher behavior. |

The training procedure can be almost identical when both use the same supervised objective.

Distillation is therefore not a completely separate optimization algorithm. It is a knowledge-transfer strategy that can use supervised training, specialized losses, or other learning objectives.

## 6. Distillation vs. Other Model Optimization Techniques

| Technique | What changes? | Main objective |
|---|---|---|
| Distillation | Student learning signals | Transfer useful knowledge or behavior |
| Fine-tuning | Model parameters | Adapt a pretrained model |
| LoRA | Trainable adapter parameters | Efficient fine-tuning |
| Quantization | Numerical representation | Reduce memory and potentially improve efficiency |
| Pruning | Model parameters or structures | Remove less useful components |

These techniques can be combined.

For example:

1. Generate training data using a teacher model.
2. Distill a smaller student model.
3. Apply LoRA to adapt the student to a specialized task.
4. Quantize the student for local deployment.

## 7. Practical Considerations

Before starting a distillation experiment, consider the following.

### Teacher selection

Choose a teacher that performs well on the target tasks.

A larger model is not automatically a better teacher. Output quality, factual reliability, task relevance, licensing, and access to training signals all matter.

### Student selection

Choose a student with an architecture and parameter count appropriate for the intended hardware.

Check whether the selected training framework supports the model.

### Dataset quality

Teacher-generated data can contain:

- Incorrect facts.
- Repetitive responses.
- Inconsistent formatting.
- Unsupported claims.
- Biases inherited from the teacher.

Review and validate generated examples before training.

### Evaluation

Evaluate the student independently.

Useful measurements include:

- Task accuracy.
- Response quality.
- Instruction following.
- Hallucination rates.
- Tokens per second.
- Peak RAM and VRAM usage.
- Model storage size.

Compare teacher and student using the same evaluation prompts and conditions wherever possible.

## 8. Limitations

Distillation has important limitations:

1. The student may not reproduce all teacher capabilities.
2. Teacher-generated data can transfer mistakes and biases.
3. Poorly selected prompts can produce an unrepresentative dataset.
4. Logit-based distillation requires access to internal teacher outputs.
5. Training still requires computational resources.
6. A smaller parameter count does not guarantee faster inference.
7. Model and dataset licensing may restrict generation, training, or redistribution.

Distillation should be treated as an experimental model-development process, not a guaranteed compression method.

## 9. When Should You Use Distillation?

Distillation is worth exploring when:

- A larger teacher performs well on a specific task.
- You need a smaller model for local deployment.
- You can generate or access suitable training signals.
- You have a representative evaluation dataset.
- The student meets your quality and hardware requirements.

It may not be appropriate when the smaller model cannot learn the required capabilities, teacher data is unavailable, or the training cost outweighs the deployment benefits.
